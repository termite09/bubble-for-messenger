# Windows — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app builds and runs on Windows 11 with the same look and behaviour, from the same source, with macOS unchanged.

**Architecture:** One pure module, `lib/platform.js`, answers what the platform can do (window levels, Spaces, vibrancy, the `roundedCorners` option, Dock, Homebrew). Main-process modules take those answers as an injectable `caps` argument (default: this platform's) and branch on them. Without window levels, `floating-window.js` keeps the level order by hand from a pure `lib/stacking.js`. CI tests on Windows too; the release workflow builds on both OSes and publishes from one job.

**Tech Stack:** Electron 44, Node 22+, `node --test`, electron-builder 26 (nsis + portable), GitHub Actions. No new dependencies.

**Spec:** `docs/specs/2026-09-16-windows-design.md`

## Global Constraints

- **macOS is unchanged.** Every capability is `true` on `darwin`; every existing test keeps passing without modification. Any darwin-path change is a bug.
- Capabilities are asked by name (`caps.spaces`), never by OS (`process.platform === 'win32'`) outside `lib/platform.js`.
- No tray icon, no Windows-specific visuals, no new settings. The `overFullscreen` and `glass` values stay in settings.json; only their rows hide.
- Every main-process function that branches takes `caps = CAPS` as its last option so tests can pass `capabilities('win32')`.

```js
// src/lib/platform.js
// What the platform can do, by name: main-process code asks about a capability, never about
// the OS. Every one of these is macOS today; the point of the list is that Windows (and a
// Linux later) is a matter of answers here, not of `process.platform` checks elsewhere.
function capabilities(platform) {
  const darwin = platform === 'darwin';
  return Object.freeze({
    windowLevels: darwin, // NSWindow levels; elsewhere every topmost window is one tier
    spaces: darwin, // setVisibleOnAllWorkspaces means something
    vibrancy: darwin, // setVibrancy exists; elsewhere the card is opaque
    roundedCornersOption: darwin, // the BrowserWindow option; Windows 11 rounds on its own
    dock: darwin,
    homebrew: darwin,
  });
}

const CAPS = capabilities(process.platform);

module.exports = { capabilities, CAPS };
```

```js
// src/lib/stacking.js
// The level order, for a platform without window levels. macOS keeps an always-on-top window
// at the level it was given ('screen-saver' above 'floating'); Windows has one topmost tier
// where the last window shown is on top. So when a window shows there, every visible window
// of a higher level is raised over it again — lowest first, so the highest ends on top.
const LEVEL_RANK = Object.freeze({
  normal: 0,
  floating: 1,
  'torn-off-menu': 2,
  'modal-panel': 3,
  'main-menu': 4,
  status: 5,
  'pop-up-menu': 6,
  'screen-saver': 7,
});

const rank = (level) => LEVEL_RANK[level] ?? LEVEL_RANK.normal;

// The entries to raise, in order, when a window at `shownLevel` has just been shown.
function raiseOrder(shownLevel, entries) {
  const shown = rank(shownLevel);
  return entries
    .filter((e) => e.visible && rank(e.level) > shown)
    .sort((a, b) => rank(a.level) - rank(b.level));
}

module.exports = { LEVEL_RANK, raiseOrder };
```

```js
const { BrowserWindow, ipcMain } = require('electron');
const path = require('path');
const { joinAllSpaces } = require('./workspaces');
const { CAPS } = require('../lib/platform');
const { raiseOrder } = require('../lib/stacking');

const RENDERER = path.join(__dirname, '..', 'renderer');

// Without window levels (Windows: one topmost tier, last shown on top) the level order is
// kept by hand: every window is recorded with its level, and when one shows, the visible
// windows of higher levels are raised over it again (lib/stacking says which, in what order).
const stacked = [];
function keepAbove(win, level) {
  const entry = { level, win };
  stacked.push(entry);
  win.on('show', () => {
    const others = stacked.map((e) => ({ level: e.level, visible: e.win.isVisible(), win: e.win }));
    for (const e of raiseOrder(level, others)) e.win.moveTop();
  });
  win.on('closed', () => {
    const i = stacked.indexOf(entry);
    if (i >= 0) stacked.splice(i, 1);
  });
}

// Every window of the app is one of these: frameless, floating at its level, on every Space
// (or one, by the full-screen setting), never full-screenable itself, and a sandboxed renderer
// that reaches main only through its preload's contextBridge. `page`/`preload` name files in
// src/renderer; a window that loads a remote site passes `url` and no page, and may pass the
// `userAgent` the site should see (set before the first load). `caps` is the platform's
// capabilities (lib/platform); the options only macOS knows are dropped where it lacks them.
function createFloatingWindow({
  level = 'floating',
  width,
  height,
  x,
  y,
  page,
  preload,
  url,
  userAgent = null,
  overFullscreen = true,
  focusable = true,
  transparent = true,
  hasShadow = !transparent,
  roundedCorners,
  visualEffectState,
  webPreferences = {},
  caps = CAPS,
  ...rest
}) {
  const win = new BrowserWindow({
    width,
    height,
    x,
    y,
    frame: false,
    transparent,
    hasShadow,
    resizable: false,
    fullscreenable: false,
    alwaysOnTop: true,
    skipTaskbar: true,
    focusable,
    show: false,
    ...(caps.roundedCornersOption && roundedCorners !== undefined ? { roundedCorners } : {}),
    ...(caps.vibrancy && visualEffectState !== undefined ? { visualEffectState } : {}),
    ...rest,
    webPreferences: {
      contextIsolation: true,
      nodeIntegration: false,
      sandbox: true,
      ...(preload ? { preload: path.join(RENDERER, preload) } : {}),
      ...webPreferences,
    },
  });
  win.setAlwaysOnTop(true, level);
  if (!caps.windowLevels) keepAbove(win, level);
  joinAllSpaces(win, overFullscreen, caps);
  if (userAgent) win.webContents.setUserAgent(userAgent);
  if (page) win.loadFile(path.join(RENDERER, page));
  else if (url) win.loadURL(url);
  return win;
}
```

### Task 10: Release: build on both, publish from one

**Files:**

- Modify: `.github/workflows/release.yml`

**Interfaces:**

- Consumes: the artifact names from Task 8 and the existing mac names `Bubble-<v>-arm64.dmg`, `Bubble-<v>-arm64-mac.zip`.
- Produces: workflow artifacts `mac` and `windows` on every run (the dry run stops there); on a tag, a release with five assets: dmg, zip, setup exe, portable exe, `SHA256SUMS`.

- [ ] **Step 1: Rewrite the workflow**

Replace `.github/workflows/release.yml` from `jobs:` onward (keep the header comment and `on:` block, and extend the comment: `Two jobs: 'build' runs on macOS and Windows and uploads what each made as a workflow artifact — the dry run stops there, and those artifacts are what a tester downloads; 'publish' collects both, checksums everything and makes the release.`):

```yaml
jobs:
  build:
    strategy:
      matrix:
        include:
          - os: macos-latest
            target: --mac
            name: mac
          - os: windows-latest
            target: --win
            name: windows
    runs-on: ${{ matrix.os }}
    permissions:
      contents: read
    outputs:
      version: ${{ steps.version.outputs.version }}

    steps:
      - name: Check out app repo
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

      - name: Set up Node
        uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version: 22
          cache: npm

      - name: Read app version
        id: version
        shell: bash
        env:
          DRY_RUN: ${{ github.event_name == 'workflow_dispatch' }}
        run: |
          VERSION="$(node -p "require('./package.json').version")"
          test -n "$VERSION"
          if [ "$DRY_RUN" != "true" ] && [ "v${VERSION}" != "$GITHUB_REF_NAME" ]; then
            echo "Tag ${GITHUB_REF_NAME} does not match package.json version ${VERSION}." >&2
            exit 1
          fi
          echo "version=$VERSION" >> "$GITHUB_OUTPUT"

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

      - name: Build
        # electron-builder auto-publishes when it detects CI; the publish job
        # handles the release itself.
        run: npm run build -- ${{ matrix.target }} --publish never

      - name: Keep only the installable files
        shell: bash
        run: |
          VERSION="${{ steps.version.outputs.version }}"
          mkdir -p out
          case "${{ matrix.name }}" in
            mac)     cp "dist/Bubble-${VERSION}-arm64.dmg" "dist/Bubble-${VERSION}-arm64-mac.zip" out/ ;;
            windows) cp "dist/Bubble-${VERSION}-x64-setup.exe" "dist/Bubble-${VERSION}-x64-portable.exe" out/ ;;
          esac
          ls -l out

      - name: Upload build artifact
        uses: actions/upload-artifact@043fb46d1a93c77aae656e7c1c64a875d1fc6a0a # v7.0.1
        with:
          name: ${{ matrix.name }}
          path: out/
          if-no-files-found: error

  publish:
    needs: build
    if: ${{ github.event_name != 'workflow_dispatch' || !inputs.dry_run }}
    runs-on: ubuntu-latest
    permissions:
      contents: write

    steps:
      - name: Check out app repo
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

      - name: Download build artifacts
        uses: actions/download-artifact@3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c # v8.0.1
        with:
          path: dist
          merge-multiple: true

      - name: Checksum the artifacts
        id: sums
        run: |
          VERSION="${{ needs.build.outputs.version }}"
          cd dist
          sha256sum "Bubble-${VERSION}-arm64.dmg" "Bubble-${VERSION}-arm64-mac.zip" \
            "Bubble-${VERSION}-x64-setup.exe" "Bubble-${VERSION}-x64-portable.exe" | tee SHA256SUMS
          echo "dmg=dist/Bubble-${VERSION}-arm64.dmg" >> "$GITHUB_OUTPUT"

      - name: Upload release assets
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          VERSION="${{ needs.build.outputs.version }}"
          TAG="v${VERSION}"
          ASSETS=(
            "dist/Bubble-${VERSION}-arm64.dmg"
            "dist/Bubble-${VERSION}-arm64-mac.zip"
            "dist/Bubble-${VERSION}-x64-setup.exe"
            "dist/Bubble-${VERSION}-x64-portable.exe"
            "dist/SHA256SUMS"
          )

          # Release notes: the changelog's top section (this version), not the whole file.
          awk '/^## /{ if (seen) exit; seen = 1; next } seen' CHANGELOG.md > release-notes.md

          if gh release view "$TAG" >/dev/null 2>&1; then
            gh release upload "$TAG" "${ASSETS[@]}" --clobber
          else
            gh release create "$TAG" "${ASSETS[@]}" --title "Bubble for Messenger ${VERSION}" --notes-file release-notes.md
          fi

      # The tap token is exposed to this one step only (the `secrets` context is not
      # allowed in a step `if`, hence the probe writing an output).
      - name: Is the tap token configured?
        id: tap
        run: echo "enabled=${{ secrets.HOMEBREW_TAP_TOKEN != '' }}" >> "$GITHUB_OUTPUT"

      - name: Update Homebrew tap cask
        if: ${{ steps.tap.outputs.enabled == 'true' }}
        env:
          HOMEBREW_TAP_TOKEN: ${{ secrets.HOMEBREW_TAP_TOKEN }}
        run: bash .github/scripts/update-homebrew-tap.sh "${{ needs.build.outputs.version }}" "${{ steps.sums.outputs.dmg }}"
```

The action SHAs above are the `v7.0.1` / `v8.0.1` tag commits as resolved on 16 Sept 2026 (`gh api repos/actions/<repo>/git/ref/tags/<tag> --jq .object.sha`); `download-artifact` v8 keeps the `path` and `merge-multiple` inputs used here.

- [ ] **Step 2: The cask script needs no change**

`.github/scripts/update-homebrew-tap.sh` takes `<version> <dmg-path>` and computes the checksum itself with `shasum -a 256` — which exists on `ubuntu-latest` (it ships with perl). Nothing in it depends on the job layout. Leave it alone.
